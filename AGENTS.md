# Инструкции для агента

Telegram-бот на Go: капча, модерация, ИИ-антиспам и статистика. Отвечай пользователю по-русски.
Описание поведения и запуска — в `README.md`; значения env — в `.env.example` и `internal/config/config.go`.

## Карта кода

| Область | Где смотреть |
|---|---|
| Запуск, конфигурация | `cmd/bot/main.go`, `internal/config/` |
| Маршрутизация, доступ | `internal/bot/bot.go`, `access.go`, `approval.go` |
| Капча, приветствие, ответ | `internal/captcha/`, `internal/bot/handlers.go`, `welcome.go`, `replywait.go` |
| Модерация, карантин | `internal/bot/modcmd.go`, `unmod.go`, `quarantine.go`, `actions.go` |

| Тексты и архивы сообщений | `internal/bot/{capture,archive,replywatch}.go`, `internal/archive/`, `cmd/msgtool/` |

## Проверки

```sh
gofmt -l .
make vet
go test -tags stdjson -race -count=1 -skip '^TestLive' ./...
make build
```

Go-команды сборки и анализа запускай с `-tags stdjson`: альтернативный JSON-декодер telego вызывал панику на типизированном nil. Makefile и CI уже используют этот тег для сборки, vet и тестов.
`TestLive*` обращаются к реальным LLM API при наличии ключей в окружении; запускай их только в рамках явно запрошенной интеграционной проверки.
Для изменений кода добавляй регрессионные тесты на изменённое поведение; для правок документации достаточно проверки ссылок и согласованности команд.

## Важные ограничения

- **Маршрутизация:** telego выбирает первый подходящий обработчик. Команды идут до `handlePrivateText`, групповой fallback — после него; новые типы апдейтов добавляй в `AllowedUpdates`. Recovery-middleware регистрируется до маршрутов.
- **Доступ:** обслуживаемые чаты проходят `chatServiceable` (allowlist + одобрение). Ошибка чтения одобрения закрывает доступ. Используй `canManageChat` и существующие проверки владельца; ошибка Telegram API сама по себе не доказывает, что пользователь не админ.
- **Модерация:** проверяй цель и права на каждом пути, включая callbacks. Отмена капчи/ожидания ответа не должна снимать новый `/mute`, оставлять вечное ограничение или запускать отложенное наказание после разбана.
- **Капча:** дубли входа подавляются через `BeginKickoff`; ответ, таймер и ручное одобрение разрешают состояние атомарно (`Take`/`TakeMatch`). Старые кнопки проверяются по идентичности сообщения, включая ephemeral ID. Срок жизни строки pending связан с результатом операции: успешный ответ не должен воскреснуть после рестарта, неудавшееся наказание должно оставаться повторяемым.
- **Ограничения пользователя:** при восстановлении используй права чата через `release`, учитывай карантин. Проверяй рестарт, выход пользователя и повышение до админа на каждом этапе проверки.
- **Фоновые задачи:** внутри `Bot` запускай через `b.goSafe`; длительная работа использует `runCtx`. Завершающие действия, которым нужно пережить отмену handler/shutdown, используют существующие `liveCtx`/detached helpers с таймаутом. Writer сообщений завершается до закрытия БД.
- **SQLite:** свежая схема — `schema.sql`; новые колонки существующих таблиц также требуют миграций в `db.go`. Для данных с `chat_id` проверь `MigrateChat`: настройки переносятся, недействительные после смены чата message ID сбрасываются. Пул ограничен одним соединением: не обращайся к `DB` в обход незакрытых rows/tx на этом соединении.
- **Статистика:** календарные дни — `storage.StatsLocation` (МСК), через `DayOf`; внутренние диапазоны имеют исключительную верхнюю границу. Меню и дайджест используют `statsRange`. Новые `EventKind` учитывай в `QueryStats`; не удваивай итог воронки при переходе от капчи к ожиданию ответа или ручной модерации.
- **ИИ и спам:** ошибка/неоднозначный ответ LLM пропускает пользователя; право обычного участника голосовать при ошибке БД не предоставляется. Глобальная запись спамера и кросс-бан допустимы только после успешного локального бана. Изменения общих промптов/парсера проверяй для всех провайдеров.
- **Интерфейс:** передавай `threadID` в форумных чатах, обновляй форматтеры и парсеры callback data вместе. Экраны ЛС отправляй через `sendScreen`. Кнопки ограничивай по визуальной ширине через `truncateLabelWidth`/`labelBudget`; текст — по рунам, Telegram entities — по UTF-16. Пользовательский HTML экранируй.
- **Капча-картинка:** при добавлении эмодзи нужен PNG-глиф в `internal/captcha/assets/`; полноту проверяет `TestAllEmojiGlyphsPresent`. Сохраняй `NOTICE.md` сторонних ресурсов.
- **Архив:** сначала записать/объединить дневной файл, затем удалять только прочитанные строки через `DeleteDayThrough(maxID)`. Поздняя запись не должна затереть существующий архив. `MESSAGE_ARCHIVE_HOT_DAYS` задаёт горячее окно, а не срок удаления архивов.
- **Данные:** ключи, `.env`, БД, логи и реальные тексты чатов не должны попадать в коммиты или отчёты. Захват сообщений, снимки reply-watch, LLM-запросы и уведомления — разные каналы хранения/передачи; не описывай приватность одного флага как гарантию для всех остальных.

## Ревью и выпуск

Для комплексного ревью используй `.agents/skills/full-review/SKILL.md`; порядок первого аудита — `docs/review.md`.
Документация описывает намерения: расхождения с кодом и опасные ранее принятые решения тоже подлежат ревью.
Исправления делай в рамках задачи; подтверждённые дефекты отделяй от гипотез и предложений по стилю.

Правки документации, тестов и внутренний рефакторинг не требуют релиза. Если задача включает релиз, формат записи в `CHANGELOG.md` — `## vX.Y.Z — YYYY-MM-DD` и список `- `: файл встроен в бинарь и разбирается ботом.
Push в `main` запускает сборку прод-образа, который подхватывает автодеплой. При согласованном выпуске тег и коммит отправляются вместе: `git push --atomic origin main vX.Y.Z`.
