# Картиночная капча (режим `image`) + версионность бота

Дата: 2026-06-12
Статус: одобрено (брейнсторминг в сессии Claude Code)

## Зачем

Текущая капча («выбери <i>енота</i>» + 6 кнопок) уязвима для ботов с парсингом текста:
название цели лежит в текстовом канале, словарь из ~43 пар «слово → эмодзи» собирается
за полчаса. Картиночный режим убирает ответ из текста полностью — он существует только
в пикселях. Классы атакующих:

- тупые боты (не жмут кнопки) — режутся и текущей капчей, без изменений;
- **парсинг-боты — ломаются полностью** (главная цель этой фичи);
- VLM-боты (GPT-4V-класс) — не барьер, но налог: getFile + инференс на каждый заход;
- люди-спамеры — без изменений (их закроет будущая пост-капча защита, отдельная фича).

Сознательное решение: искажения **умеренные**. Гонка с VLM проигрышна — сильные
искажения сначала ломают людей на телефонах и только потом модели. Цель — отсечь
дешёвый текстовый парсинг, не победить компьютерное зрение.

Бонус: режим language-agnostic — сопоставление «картинка ↔ кнопка» не требует русского.

Вторая часть спеки — версия бота в `/info` и в стартовом уведомлении владельцам
(после cron-деплоя видно, что выкатилось).

## Не-цели

- Анти-VLM устойчивость.
- Замена существующих режимов: `circles` остаётся дефолтом, `image` — opt-in per chat.
- Картиночный вариант для режима кружков (цветовые искажения путают цвета — людям хуже,
  чем ботам; кружки различаются только цветом).
- Пост-капча эвристики (отдельная будущая фича).

## 1. UX и настройки

- `captcha_mode` принимает третье значение `image` (`circles` | `emoji` | `image`).
  Неизвестные значения, как и раньше, фоллбек на `circles`. Схема БД не меняется
  (колонка уже TEXT).
- Ряд режимов в настройках чата: «🟢 Кружки | 🦋 Эмодзи | 🖼 Картинка»
  (`menu.go`: `captchaModeRow`, валидация в `cmode`-кейсе, `captchaModeLabel`).
- Флоу новичка: приходит **фото** (искажённый глиф правильной эмодзи) с подписью
  «Привет, {mention}! Для защиты от спама выбери эмодзи, наиболее похожую на
  картинку, за N секунд.» и той же клавиатурой: 6 эмодзи-кнопок (по одной из каждой
  категории — переиспользуется выборка `newEmoji()`) + «✅ Впустить (для админов)».

## 2. Генерация изображения (`internal/captcha`)

### Глифы

- Noto Emoji PNG 128×128 (Apache 2.0), **только наши ~43 эмодзи**, в репозитории
  `internal/captcha/assets/emoji_uXXXX.png`, вшиваются через `go:embed` (~200 КБ).
- Маппинг эмодзи → имя файла по кодпоинтам; вариационные селекторы (FE0F у ☀️❄️ и
  т.п.) в имени файла отбрасываются, как принято в Noto.
- Файл NOTICE/комментарий с указанием лицензии Apache 2.0.
- Цветные эмодзи нельзя отрендерить шрифтом в чистом Go (COLR/CBDT не
  поддерживаются) — поэтому готовые PNG. CGO_ENABLED=0 сохраняется.

### Искажения

Канвас ~384×256. Пайплайн (все параметры случайные в указанных пределах):

1. светлый неоднородный фон (градиент + пятна светлых тонов);
2. глиф: масштаб 0.8–1.2, поворот ±25°, случайная позиция с отступами от краёв
   (аффинное преобразование, `golang.org/x/image/draw`, CatmullRom);
3. волновая деформация — синусоидальный сдвиг строк (амплитуда 3–6 px,
   период 40–80 px);
4. 2–4 полупрозрачные тёмные линии поверх (толщина 2–3 px);
5. точечный шум ~2% пикселей.

**Без цветовых сдвигов** — узнаваемость для человека приоритетна. На картинке
Noto-стиль, на кнопках — платформенный стиль клиента юзера: человек сопоставляет
сущности («лиса = лиса»), попиксельное сравнение бессмысленно.

Выход — PNG (encode стандартным `image/png`).

### API пакета

- Рендер принимает `*rand.Rand` (внутренняя функция) — детерминируемость в тестах
  фиксированным сидом; публичная обёртка использует обычный источник.
- Единственная новая зависимость: `golang.org/x/image`.

### Надёжность

- Ошибка рендера (отсутствующий глиф, сбой пайплайна) → **тихий фоллбек на текстовый
  emoji-режим** до отправки: капча уходит всегда.
- Ошибка `SendPhoto` → текущее поведение всех режимов: release + return.

## 3. Интеграция

Меняется:
- `internal/captcha`: `image.go` (рендер) + `assets/` + маппинг глифов; режим
  `ModeImage`.
- `runCaptcha`: для `image` — `SendPhoto` с caption (HTML) + та же клавиатура +
  `WithMessageThreadID` при threadID != 0.
- `menu.go`: третья кнопка режима; `access.go::effectiveCaptchaMode`: кейс `image`.

**Не меняется**: `store`, `pending_captchas` (correct_idx/thread_id те же),
`handleCallback`, `handleApproveCallback`, `waitTimeout`, рестор после рестарта,
`DeleteMessage` (фото удаляется так же). Чисто контентное изменение.

## 4. Версионность

- `cmd/bot/main.go`: `var version = "dev"`, заполняется линкером:
  `-ldflags "-X main.version=$(git describe --tags --always --dirty)"`.
- Прокидывается в `bot.New(cfg, log, version)`; показ:
  - `/info`: строка «Версия: <code>…</code>»;
  - стартовое 🟢-уведомление владельцам: «Версия: …».
- Makefile: `VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)`;
  цели `build` и `docker-up` используют её (`docker-up` передаёт build-arg).
- Dockerfile: `ARG VERSION=dev` в builder-слое + ldflags. `.git` исключён
  `.dockerignore`-ом (и это правильно — кэш/размер контекста), поэтому версия
  приходит снаружи аргументом, а не вычисляется внутри образа.
- docker-compose.yml: `build.args.VERSION: ${VERSION:-dev}`. Канонический путь
  деплоя — `make docker-up` (экспортирует VERSION сам); голый
  `docker compose up -d --build` даст «dev» — в README заметка для cron-скрипта:
  либо `make docker-up`, либо `VERSION=$(git describe --tags --always) docker compose up -d --build`.
- Тегов пока нет → версия = короткий хэш (например, `976926b`). Рекомендация:
  тегнуть `v1.0.0` после мержа фичи; `git describe` дальше сам даст
  `v1.0.0-N-g<hash>`.

## 5. Тесты

- Рендер для **каждого** из ~43 глифов: не паникует, валидный непустой PNG
  разумного размера (decode обратно + границы байтов), фиксированный сид.
- Маппинг: для каждого Token всех emoji-категорий существует файл глифа (ловит
  рассинхрон пула эмодзи и assets при будущих правках). Глифы кружков не нужны —
  image-режим работает только с emoji-пулом (см. «Не-цели»).
- Фоллбек: рендер с заведомо отсутствующим глифом → ошибка без паники
  (фоллбек-ветка в `runCaptcha` за счёт этого тривиальна).
- `effectiveCaptchaMode` / `cmode`-валидация принимают `image`.
- Форматирование версии в `/info` (unit на хелпер, если выделится).

## Риски

- Визуальные коллизии похожих эмодзи между категориями (🐟/🐬) — митигировано
  составом пулов: в выборке по одной эмодзи из каждой из 6 визуально далёких
  категорий.
- Glyph-файл забыли добавить при расширении пула — ловится тестом маппинга.
- Telegram-сжатие фото — канвас 384×256 переживает джипегизацию без потери
  узнаваемости (глиф крупный).
