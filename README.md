# AntiSpamBot

Telegram-бот на Go: проверяет новичков капчей, помогает модерировать чаты и ведёт статистику. Работает через long polling; состояние хранится в SQLite.

## Возможности

- Три режима капчи: цветные кружки, эмодзи, картинка. Напоминания и порог бана настраиваются для каждого чата.
- После капчи: ничего, приветствие или приветствие с обязательным осмысленным ответом. Дополнительно — текстовый карантин новичка.
- Модерация, ручной пропуск, доверенные пользователи и голосование по жалобе `/spam`.
- ИИ-антиспам сообщений и профилей: Groq → Gemini → GigaChat; порядок задаётся через env. Подозрение выносится на голосование, голос админа решает сразу. Подтверждённый локальный спам-бан пополняет общую базу и запускает кросс-бан в других обслуживаемых чатах.
- Статистика и ежедневные сводки по московским календарным дням; настройки через личное меню бота.
- Уведомления владельцам, ответ в чат из ЛС от имени бота, наблюдение за удалением/правками ответа новичка.
- Восстановление незавершённых проверок после рестарта, форумные топики и опциональные эфемерные сообщения.

История версий — [CHANGELOG.md](CHANGELOG.md), в боте — `/whatsnew`.

## Запуск

1. Создай бота у [@BotFather](https://t.me/BotFather), получи токен и выключи Group Privacy.
2. Скопируй настройки и заполни `BOT_TOKEN`. Укажи `OWNER_IDS`, если нужно подтверждать добавление в новые чаты и управлять всеми чатами.

```sh
cp .env.example .env
```

Владельцы должны хотя бы раз написать боту `/start`, чтобы он мог отправлять им сообщения. Для разработки используй отдельного бота и тестовый чат.

Локально нужен Go по [go.mod](go.mod):

```sh
go mod download
make run
```

`.env` подхватывается автоматически. База по умолчанию — `./bot.db`. Makefile включает обязательный для проекта build tag `stdjson`.

Для запуска готового прод-образа нужен Docker Compose v2:

```sh
docker compose pull bot
docker compose up -d --no-build
docker compose logs -f bot
```

Для сборки из текущих исходников — `make docker-up`. Версия в бинаре проставляется Makefile/CI; непосредственная сборка через compose без `VERSION` даёт `dev`.

Добавь бота администратором группы с правами блокировки участников и удаления сообщений. Если заданы владельцы, новый чат, добавленный другим человеком, ждёт их одобрения в ЛС; без `OWNER_IDS` новые чаты одобряются автоматически.

В ЛС: `/start` → «Мои чаты» → чат → «Настройки». Владелец управляет всеми обслуживаемыми чатами, админ — своими. Если задан `ALLOWED_CHATS`, при превращении группы в супергруппу новый ID нужно добавить в список.

Перед выходом бота через меню заверши активные капчи: впусти или исключи участников. Пока есть незавершённая проверка входа, бот остаётся в чате, чтобы не оставить человеку бессрочный мут.

## Команды

Полный список и пояснения — `/help`. Основные:

| Команды | Доступ и назначение |
|---|---|
| `/start`, `/chats` | ЛС: меню, доступные чаты и их настройки |
| `/help`, `/whatsnew` | Справка и изменения; доступны также в группе |
| `/info`, `/logs` | Только владельцы в ЛС: состояние бота и лог-файл |
| `/kick`, `/ban`, `/mute N` | Админ/владелец в группе: кик, бан, мут; `N` — минуты, также `10m`, `2h`, `1d` |
| `/del` (`/delete`) | Админ/владелец: удалить сообщение реплаем |
| `/unban`, `/fullunban`, `/unmute`, `/whitelist` | Админ/владелец: восстановление; `/fullunban` также снимает баны в остальных чатах бота, `/whitelist` даёт вход без капчи |
| `/trust` | Админ/владелец: досрочно снять карантин |
| `/spam` | Жалоба реплаем: доверенный участник открывает голосование, админ/владелец сразу запускает спам-бан |
| `/replywithbot` (`/rwb`) | Только владелец: ответ от имени бота в группе; в ЛС достаточно ответа реплаем на пересланное ботом сообщение или связанную карточку |

Модерация принимает реплай или известный боту `@username`; некоторые команды без цели предлагают список последних действий. `/del` и `/spam` требуют реплая, `/replywithbot` — реплая и текста ответа. `/mute` требует срок. Кик/бан стирают сообщения цели, поэтому для проверки используй тестовый чат.

## Настройки

Полный список env с дефолтами — [.env.example](.env.example); разбор и валидация — [internal/config/config.go](internal/config/config.go). Изменения env применяются после перезапуска. Настройки отдельного чата меняются через меню.

| Группа | Переменные |
|---|---|
| Доступ | `BOT_TOKEN`, `OWNER_IDS`, `ALLOWED_CHATS` |
| Дефолты капчи | `CAPTCHA_STAGE_MINUTES`, `MAX_ATTEMPTS`, `CAPTCHA_DELAY_MS` |
| Статистика | `NEWCOMER_DAYS`, `SILENT_ANNOUNCE_DAYS`, `DAILY_STATS_UTC_HOUR` |
| Хранение и логи | `DB_PATH`, `LOG_LEVEL`, `LOG_FILE` |
| ИИ | Ключи/модели `GROQ_*`, `GEMINI_*`, `GIGACHAT_*`, порядок `AI_PROVIDER_ORDER` |
| Захват сообщений | `MESSAGE_CAPTURE_ENABLED`, `ARCHIVE_DIR`, `MESSAGE_ARCHIVE_HOT_DAYS` |
| Наблюдение за ответом | `REPLY_WATCH_ENABLED`, `REPLY_WATCH_CHAT_ID` |

Для ИИ нужен хотя бы один ключ и включённый антиспам в настройках чата. Ошибка всех провайдеров не приводит к наказанию.

## Данные и приватность

- SQLite хранит события модерации, счётчики, ID и имена пользователей, настройки и незавершённые проверки. Статистика и управление чатами доступны владельцам и соответствующим админам.
- При включённом ИИ-антиспаме провайдерам передаются текст/подпись сообщения и сведения об авторе; проверка профиля включает доступное bio и количество фото. Файлы медиа и аватары в LLM не отправляются. Факты проверки записываются в логи, доступные владельцам.
- `MESSAGE_CAPTURE_ENABLED` по умолчанию выключен. При включении сохраняет текстовый след сообщений и правок, включая сведения о реплаях. После горячего окна данные переходят в дневные `.jsonl.zst`; автоматического удаления архивов нет. Выключение захвата уже накопленные данные не удаляет.
- `REPLY_WATCH_ENABLED` по умолчанию включён: снимок ответа новичка хранится отдельно от общего захвата. Пробы копируют сообщение, включая медиа при его наличии, в служебный чат и сразу удаляют копию. Чат должен быть приватным; по умолчанию используется ЛС владельца с наименьшим ID. Владельцы получают уведомления об удалениях/правках.
- Сообщения также могут пересылаться владельцам в уведомлениях о спаме и ответах новичков. Отключённый общий захват не отключает ИИ-логи, уведомления и reply-watch. Перед включением этих функций предупреди участников.

## Эксплуатация

Compose хранит БД, лог и архивы в volume `bot-data`: `/data/bot.db`, `/data/bot.log`, `/data/archive`. `docker compose down` сохраняет данные; `down -v` удаляет volume.

Обновление готового образа:

```sh
docker compose pull bot
docker compose up -d --no-build
```

[CI](.github/workflows/ci.yml) проверяет форматирование, vet, уязвимости, тесты с race detector и сборку. После успешных проверок push в `main` публикует `ghcr.io/menand/antispambot:latest` и тег версии.
[scripts/auto-deploy.sh](scripts/auto-deploy.sh) предназначен для Linux-сервера: забирает образ, проверяет запуск и при жёстком сбое пытается вернуть предыдущий образ. Пример cron (путь замени своим):

```cron
* * * * * /path/to/AntiSpamBot/scripts/auto-deploy.sh >> /var/log/antispam-deploy.log 2>&1
```

На время ручного отката останови cron, иначе он снова подтянет `latest`. Совместимость старого бинаря с уже обновлённой БД требует отдельной проверки.

SQLite работает в WAL: для онлайн-бэкапа используй `sqlite3 .backup`, а не копирование одного `bot.db`. Сохраняй также архивы и конфигурацию; восстановление проверяй на отдельной копии. В прод-образе `sqlite3` не установлен.

Если бот не реагирует, проверь его права в чате, одобрение владельцем, `ALLOWED_CHATS`, Privacy Mode и `docker compose logs --tail=100 bot`.

## Разработка и ревью

```sh
make build            # bin/bot и bin/msgtool
make vet
go test -tags stdjson -race -count=1 -skip '^TestLive' ./...
gofmt -l .            # пустой вывод = код отформатирован
```

`make test` запускает race-тесты, включая `TestLive*`, если экспортированы ключи провайдеров. Команда выше исключает реальные LLM-запросы. `govulncheck -tags stdjson ./...` также входит в CI; локально доступен `make vuln`. `make lint` требует установленного `golangci-lint` v2.
