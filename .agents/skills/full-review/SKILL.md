# Полное ревью AntiSpamBot

Прочитай корневой `AGENTS.md`. Для аудита всего репозитория используй порядок из `docs/review.md`.
По умолчанию ревью заканчивается отчётом; исправляй код, если это входит в запрос пользователя.

## Область

- «Текущие изменения» — `git status --short`, `git diff HEAD` и новые файлы, включая untracked.
- Указанный коммит — `git show <commit>`; указанные пути — эти файлы и необходимый вызывающий код.
- «Весь проект» — все исходники, тесты, сборка и эксплуатация. Не подменяй аудит проекта анализом последнего diff.
- Если область неясна, начни с рабочих изменений; при чистом дереве уточни цель, продолжая знакомиться с проектом.

## Проверка

Проследи сценарии по коду и тестам:

1. Права владельца/админа, одобрение чатов, недоверенные callback data, границы между чатами.
2. Капча → приветствие/ответ → карантин: дубли апдейтов, устаревшие кнопки, гонки, выход/повышение пользователя, ручная модерация, рестарт и shutdown.
3. Свежая/старая SQLite-БД и `MigrateChat`; атомарность голосований, статистика по МСК, сохранность сообщений и архивов.
4. LLM fallback и лимиты, доверие и голосования, локальный бан перед глобальными последствиями, данные в запросах/логах/уведомлениях.
5. Достижимость действий в меню, честность уведомлений, Unicode, HTML, форумные и эфемерные сообщения.
6. CI, Docker, healthcheck, автодеплой/откат и резервное восстановление. Команды с продовыми последствиями в рамках ревью не запускай.

Выполни базовые проверки из раздела «Проверки» в `AGENTS.md`.
При отсутствии инструментов, сети или доступа укажи ограничение. Зелёный тест не доказывает покрытие: сопоставляй критические ветки с проверяемыми сценариями.
Линтер и `govulncheck -tags stdjson ./...` запускай при наличии соответствующих инструментов; не выдавай их отсутствие за успешную проверку.

## Отчёт

Пиши по-русски. Сначала подтверждённые находки по убыванию серьёзности: P1 — срочное исправление, P2 — обычное, P3 — низкий приоритет; P0 оставь для безусловной аварийной проблемы.
Для каждой укажи `файл:строка`, конкретный триггер, последствия и направление исправления. Проверяй номера строк по текущему файлу.
Объединяй дубли. Гипотезы и вопросы выноси отдельно; ранее задокументированный компромисс не освобождает от оценки риска.
Заверши кратким статусом выполненных/пропущенных проверок и непроверенных областей. Если дефектов не найдено, скажи это без наполнения отчёта косметическими замечаниями.
